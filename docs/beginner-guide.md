# AI DevOps 零代码使用指南

这份指南是写给第一次接触软件开发、Git、CI/CD 和云平台的用户。你不需要记住技术命令，也不需要自己写代码。

## 先看懂三个角色

| 角色 | 你看到的 | 实际负责什么 |
| --- | --- | --- |
| 你 | AI 对话窗口、AI DevOps 网页 | 用中文提目标，查看结果，批准生产上线 |
| Codex / WorkBuddy | 类似聊天的工作台 | 理解需求、开发代码、测试、解释错误、准备版本 |
| AI DevOps | 浏览器控制台 | 记录版本、执行流水线、连接云、运维和审计 |

最理想的工作方式是：

```text
你用中文说“我要什么”
        ↓
Codex / WorkBuddy 写代码并测试
        ↓
AI DevOps 记录版本并执行发布流程
        ↓
你在浏览器查看结果，必要时点一次“批准”
```

你不需要理解 Git 分支、commit、Runner、Kubernetes 等技术细节。智能体和平台应该替你处理这些内容；它们只需要把最终结果、风险和需要你决定的事项用中文说明清楚。

## 现在第一次打开

### 第一步：启动平台

打开文件夹：

```text
D:\AI-DevOps
```

双击：

```text
start-ai-devops.cmd
```

浏览器会自动打开平台。平台自带放在 D 盘的 Node.js 运行时，不需要你
另外安装 Node.js 或 pnpm。首次启动时可能会先安装依赖或构建页面，
多等一会儿是正常的。

### 第二步：登录

管理员邮箱：

```text
admin@aidevops.local
```

管理员密码保存在你电脑本机的 `.env` 文件中，找到这一行：

```text
ADMIN_PASSWORD=你的密码
```

密码就是上面 `ADMIN_PASSWORD` 的值。请把它改成足够长的随机密码（至少 12 位），并且不要把这个文件或密码提交到公开仓库。

### 第三步：打开“使用指南”

登录后，点击左侧菜单的“使用指南”。里面会显示：

- 你可以做什么
- Codex / WorkBuddy 负责什么
- AI DevOps 负责什么
- 可直接复制的中文指令
- 当前还是演示模式还是真实模式

### 第四步：向智能体提出第一个需求

可以直接复制下面这段给 Codex 或 WorkBuddy：

```text
请带我完成这个项目接入 AI DevOps 的第一步。请直接检查当前项目，
告诉我它用什么技术、需要哪些发布环境、是否能部署到腾讯云、阿里云
或华为云。不要让我执行 Git 或终端命令；凡是需要我操作的地方，
请用小白能懂的步骤说明。先只做检查，不要修改生产配置。
```

智能体应该用中文告诉你：

1. 这是一个什么项目；
2. 现在能不能运行；
3. 需要准备哪些发布环境；
4. 下一步需要你做的唯一决定是什么。

如果它要求你输入 Linux 命令或解释 Git，可以直接回复：

```text
我不使用 Git，也不会操作终端。请由你负责代码、分支、测试和版本整理；
只把需要我决定或授权的事情告诉我，并用小白能懂的步骤说明。
```

## 当前版本真正能做什么

现在已经可以真实使用：

- 登录 AI DevOps；
- 登记 Gitee 公开或私有 Git 仓库，凭据加密保存；
- 从远程仓库拉取代码并记录最新 commit；
- 查看最近版本和同步状态；
- 按网站、小程序、后端 API、移动端和通用服务类型创建应用，
  同类型应用自动复用同一套字段模板；
- 按项目发起真实发布，依次同步代码、构建镜像、推送腾讯云 TCR、部署服务器并进行健康检查；
- 在发布历史中查看 commit、镜像、服务器、端口、域名、审批、步骤、日志和失败原因；
- 对生产发布执行人工审批，并在异常时自动重启、失败后回滚；
- 使用腾讯云子账号验证和全地域真实资源同步；
- 使用浏览器连接云服务器终端、管理 MySQL 与执行备份；
- 使用本地证据模式 AI Copilot，也可以接入兼容的大模型网关；
- 通过 Agent Bridge 令牌或 MCP 让不同研发智能体向平台提交交付请求；
- 查看登录、发布、同步和 AI 查询的审计记录。

### 刷新腾讯云资源并查看全部域名

1. 登录后打开“多云资源 → 云资源视图”；
2. 点击页面右上角的“同步云资源并刷新数据”按钮；
3. 按钮转圈期间表示正在真实调用腾讯云接口，通常需要几十秒，请不要重复点击；
4. 完成后页面会提示本次扫描的账号数、资源数和注册域名数；
5. 在资源分类中分别查看“注册域名”和“DNS 域名”。

两种域名不是同一份数据：

| 分类 | 含义 | 数据来源 |
| --- | --- | --- |
| 注册域名 | 当前腾讯云账号实际持有、已购买并需要续费的域名 | 腾讯云域名注册 `DescribeDomainNameList` |
| DNS 域名 | 已接入 DNSPod 解析的域名，可能有权管理解析但域名并不在本账号注册 | DNSPod `DescribeDomainList` |

注册域名会展示注册时间、到期时间、购买状态、自动续费和 DNSPod 状态。没有看到某个
域名时，先确认它确实在对应腾讯云账号下；如果腾讯云控制台能看到、平台看不到，请检查
该 CAM 子账号是否具备“域名注册只读”和“DNSPod 只读”权限。权限错误会显示腾讯云错误码
和 `RequestId`，便于排查。该刷新只读取云资源，不会修改、续费或删除任何域名。

阿里云登记时使用账号的 AccessKey ID 和 AccessKey Secret，不要填写控制台登录密码。
主账号或已获授权的 RAM 子用户都可以，建议优先使用完成最小权限授权的子用户。
AccessKey 在阿里云“RAM 访问控制”中管理；主账号可在“AccessKey 管理”创建，
子用户由管理员在用户详情中创建。平台只接收 API 凭据，不接收网页密码、验证码或 Cookie。
账号 UID 可以留空，平台验证后会自动核对；完整的 ECS/VPC/SLB/RDS 读取和云监控读取
需要对应只读权限。

腾讯云登记时使用 SecretId 和 SecretKey，在“访问管理 CAM → API 密钥管理”中获取。
主账号或已授权的 CAM 子用户都可以，不需要也不应填写腾讯云控制台登录密码。
Secret Manager 引用不是这个页面需要填写的内容。

云服务器卡片的 CPU、内存来自厂商监控接口。腾讯云 CVM、轻量应用服务器和阿里云
ECS 已接入；阿里云 ECS 需要安装云监控插件才能返回内存使用率。页面显示“暂无数据”
表示本次没有采集到有效值，不代表使用率为 0%。

仍需继续完善：

- 华为云的真实资源适配器；
- GitHub/GitLab 自动 Webhook；
- 面向公网访问的域名、HTTPS 与更完整的账号权限体系；
- 更细粒度的多环境发布策略和容量管理。

判断一次发布是否真的完成时，只看“发布与版本 → 项目发布 → 发布历史（真实部署）”，
或到“发布与版本 → 版本中心”查看全部版本。早期门禁模拟记录不再计入部署次数、
成功率和生产待审批。

## 以后每天怎么用

### 开发一个功能

复制给 Codex/WorkBuddy：

```text
请直接在当前项目开发这个功能：【功能描述】。
请自动创建功能分支、完成代码修改和测试，并告诉我改了什么、有什么风险。
不要直接修改受保护的 main 分支，也不要让我手动使用 Git。
完成后请准备一个可以在 AI DevOps 中查看和审批的发布版本。
```

你只需要：

1. 看智能体是否理解正确；
2. 看功能演示；
3. 看它列出的风险和测试结果；
4. 决定是否发布。

### 部署到云上

提交 AI DevOps 发布流水线时，可以使用：

```text
请把当前已验证的版本部署到【腾讯云/阿里云/华为云】的
【开发/预发/生产】环境。请先检查云账号连接、权限、健康阈值和回滚方案。
如果缺少授权，请停下来告诉我需要配置哪一项，不要让我在聊天里发送密码、
AK 或 SK。生产部署必须等待我在浏览器里批准。
```

不要通过聊天发送以下内容：

- 云账号密码；
- AccessKey / SecretKey；
- 服务器 SSH 登录密码；
- `.env` 里的密钥；
- 短信验证码或支付信息。

正确的做法是由智能体引导你在云控制台创建只读或受限角色，并通过安全连接方式授权。

### 查看线上问题

```text
请检查【服务名称】最近一次故障：先关联最新发布、日志、指标和云资源状态，
用大白话告诉我发生了什么、证据是什么、你有多确定。只进行只读排查；
如果需要重启、扩容、改配置或回滚，请先生成变更提案、风险和回滚步骤，
由平台管理员在 AI DevOps 中审批并执行，不要声称你能直接执行云变更。
```

## 生产批准时看什么

当页面显示“等待审批”，不要直接点击批准。先确认页面或智能体能回答：

1. 哪个应用、哪个版本；
2. 发布到开发、预发还是生产；
3. 改了什么，可能影响谁；
4. 测试和健康检查是否通过；
5. 出问题时如何回滚。

如果看不懂，直接发给智能体：

```text
请用第一次接触 DevOps 的人能听懂的方式解释这次发布。
告诉我影响范围、证据、失败概率和回滚办法。
如果你不能给出明确答案，请建议我拒绝这次发布。
```

拒绝也是正常的安全决策，不会损坏项目。

## 从其他电脑访问

当前平台运行在这台电脑上。同一个局域网里的电脑可以通过下面的地址访问：

```text
http://<你的局域网IP>:8787
```

如果打不开，需要：

1. 确认两台电脑在同一个局域网；
2. 启动平台的电脑保持开机；
3. 在 Windows 防火墙中允许 TCP 8787；
4. 不要直接开放到互联网。

IP 地址可能会变化。最可靠的方法是以启动窗口显示的局域网地址为准。

如果要让外地或公网用户访问，需要先把平台部署到云服务器，并配置域名、HTTPS、身份认证、备份和防火墙。这部分不能直接通过家庭电脑端口开放来完成。

## 遇到问题时怎么问

不用自己判断技术原因。可以复制：

```text
我在 AI DevOps 遇到了问题：【描述你看到了什么】。
请先检查平台服务和日志，用小白语言解释原因。
不要要求我手敲技术命令；请你直接处理或明确告诉我只需要点击哪里。
如果涉及删除数据、付费资源或生产变更，请先停下来向我确认。
```

常见情况：

- 网页打不开：双击 `start-ai-devops.cmd`，或把错误截图发给智能体；
- 忘记密码：查看本机 `.env` 的 `ADMIN_PASSWORD`；
- 数据不对：到“多云资源 → 云资源视图”点“同步云资源并刷新数据”做真实同步，或把“故障诊断”里的错误报告复制给智能体；
- 智能体要求自己输入 Git 命令：提示它“我不使用 Git，请你代为完成”；
- 不确定是否批准：先拒绝，再让智能体解释风险和回滚方案。

## 版本管理在哪看

| 想看什么 | 入口 |
| --- | --- |
| 代码版本历史（分支、commit、提交说明、同步时间） | 左侧"代码仓库" → 仓库卡片"最近版本" |
| 全部版本、当前版本、回滚记录 | "发布与版本" → "版本中心" |
| 单个项目的版本（commit、镜像、环境、审批、日志、回滚） | "发布与版本" → "项目发布" → 项目 → "发布历史（真实部署）" → 详情 |
| 最近发布 | "总览" → 最近发布（真实部署） |
| 谁在什么时间触发了什么版本 | "审计中心" |

### “发布历史（真实部署）”和旧“流水线历史”有什么区别

- “发布历史（真实部署）”是服务器实际发布的唯一事实源。它记录一次发布是否真的完成
  代码同步、镜像构建、TCR 推送、服务器部署、健康检查和回滚，包含可直接查看的日志与证据。
- 旧“流水线历史”来自早期门禁模拟记录，只表示质量门禁有没有执行，不代表代码已经部署到
  服务器，也不参与部署次数、发布成功率和生产待审批统计。
- 为避免重复和误解，项目详情只展示“发布历史（真实部署）”；没有旧记录时不再显示空的
  “流水线历史”页面。总览的交付成功率也只按真实部署计算。
- 项目列表中的“发布历史”是跨项目汇总，进入具体项目后只显示该项目的部署记录；两者是
  汇总与明细的关系，不是两份重复数据。

命名规则：

- 代码版本 = 分支 + 7 位 commit 短 SHA（如 master + 1a2b3c4）；
- 镜像版本 = ccr.ccs.tencentyun.com/examplespace/应用英文名:commit 短 SHA（如 agent-bridge:1a2b3c4）；
- 部署版本 = 应用 + 环境 + commit + 镜像 + 时间 + 审批与健康结果；
- 回滚目标 = 上一次成功部署的镜像标签；
- 当前未启用 v1.2.3 语义化版本号，发布固定具体 commit，不使用 latest。

### 版本中心与回滚闭环

“版本中心”直接读取真实部署记录，不另外复制一份版本数据。因此同一次部署在
总览、项目历史、版本中心和审计中心里的应用、commit、镜像、状态与时间保持一致。

版本中心支持按应用、环境和状态筛选，并标记每个应用当前成功运行的版本。只有曾经
发布成功、具有不可变镜像标签的历史版本才能成为回滚目标。

人工回滚按以下闭环执行：

1. 在版本中心或项目发布历史中打开一个历史成功版本；
2. 点击“回滚到此版本”，确认当前版本和目标版本；
3. 平台只创建“待审批”的回滚部署，不会立即修改服务器；
4. 你在发布记录中点击“批准并执行回滚”；
5. 平台用历史镜像替换容器，并执行独立的回滚健康检查；
6. 成功后生成新的“人工回滚”部署记录，失败则记录原因和自动恢复结果；
7. 全过程可在版本中心、发布历史、健康监控和审计中心追溯。

部署健康检查失败时，如果存在上一成功版本，平台会创建一条“自动回滚”部署记录并
验证历史镜像健康；持续健康监控在连续失败后也会执行相同流程。

## 智能体对接（任何智能体都能使用）

AI DevOps 是所有智能体的统一交付中枢，不绑定某个工具。Codex、WorkBuddy、
CodeBuddy、QoderCN、VS Code 智能体等都可以接入，三种方式任选其一：

| 方式 | 适合谁 | 怎么做 |
| --- | --- | --- |
| 令牌对接 | 所有智能体 | 平台设置 → 智能体对接 → 创建令牌（只显示一次），智能体凭令牌调用 `POST /api/agent/deliver` 发布、`GET /api/agent/status` 查状态、`GET /api/agent/resources` 查资源与指标 |
| MCP 对接 | Codex、Cursor 等支持 MCP 的工具 | 复制设置页的 MCP 配置 JSON 到工具配置，获得 ai_devops_deliver / ai_devops_status / ai_devops_resources / ai_devops_health 四个工具 |
| 对接指令 | 任何不支持上面两种的工具 | 复制“使用指南 → 智能体对接”里的对接指令，发给智能体即可 |

标准流程固定为：创建智能体专用令牌 → 写入本机 stdio MCP 配置 → 用
`ai_devops_health` 验证连接 → 只读检查项目并等待明确任务 → 完成开发和测试 →
确有代码改动且在用户明确要求交付后推送功能分支 → 调用 `ai_devops_deliver` →
用 `ai_devops_status` 查询结果。生产部署始终停在管理员审批。

WorkBuddy / Codex / Cursor 的本机 stdio 配置：

```json
{
  "mcpServers": {
    "ai-devops": {
      "type": "stdio",
      "command": "D:\\AI-DevOps\\runtime\\node\\node.exe",
      "args": ["D:\\AI-DevOps\\bridge\\mcp\\ai-devops-mcp.mjs"],
      "env": {
        "AI_DEVOPS_URL": "http://127.0.0.1:8787",
        "AI_DEVOPS_AGENT_TOKEN": "<粘贴新创建的智能体令牌>"
      }
    }
  }

```

桥接器会给 AI DevOps 请求自动添加
`Authorization: Bearer <AI_DEVOPS_AGENT_TOKEN>`，因此本机 stdio 模式不需要在 MCP
客户端重复配置认证头。`command` 使用项目内置 Node 的绝对路径，避免 MCP 客户端
找不到系统 `node`。当前没有公网 MCP URL；跨电脑使用前必须先完成 HTTPS、
访问控制和独立审批。

交给智能体的标准指令：

```text
你正在接入 AI DevOps。当前只做只读接入检查，不要调用 ai_devops_deliver，
也不要自动修改代码、提交、推送 Git、构建或部署。
1. 调用 ai_devops_health，确认 MCP 工具可用；
2. 只读检查当前项目的技术栈、Git 远程仓库、当前分支和未提交改动；
3. 报告连接结果、项目现状和缺失配置；没有明确开发或交付任务时停下来等待；
4. 只有用户明确要求开发并交付，且代码修改和测试完成后，才在功能分支提交并推送；
   没有代码改动、测试未通过、仓库未登记或用户未要求交付时不得推送；
5. 用户明确要求交付后才调用 ai_devops_deliver 并用 ai_devops_status 查询结果。
```

注意事项（务必遵守）：

1. 令牌就是钥匙，只在平台设置页复制，不要发到公开聊天或截图；泄露立即撤销重建；
2. 智能体只有“提交交付 + 查询自己的部署 + 查询已同步资源与指标”权限；
3. 智能体不能审批、回滚、执行云变更、读取密钥或修改平台设置；生产部署必须由平台管理员在浏览器中批准并执行；
4. 没有代码改动、测试未通过或用户没有明确要求交付时，智能体不得推送或调用交付；
5. 交付前仓库必须已在“代码仓库”中登记（Gitee 地址或平台登记名）；
6. 先 staging 验证，再 production；生产发布会暂停在审批环节；
7. 不要向智能体发送任何账号密码、验证码、Cookie 或云密钥，所有 API 凭据加密保存在本机平台。

本机对接自检（不提交交付、不访问云写接口）：
